# BULLET LAB — 총알탄 사나이 (실시간 멀티플레이 베타)

React + TypeScript + Socket.IO로 만든 16×16 퍼즐 웹게임. PC와 모바일에서 플레이할 수 있다.

## 구현된 기능

- **혼자 하기:** 2분 챌린지 / 제한시간 없는 연습, 오늘의 퍼즐, 실행 취소, 힌트(최단 경로 보장 아님), 같은 문제 링크 공유.
- **실시간 친구 대전:** 닉네임만 입력해 2~8명 방 생성 및 6자리 코드·QR 초대, 실시간 참가자 목록, 방장 시작, 3초 동시 카운트다운, 2분 타이머, 실시간 점수판과 다음 경기.
- **동일한 퍼즐:** 모든 참가자에게 같은 목표·시작 위치를 전달하지만 **서로의 로봇 위치에는 영향을 주지 않는다.**
- **서버 검증:** 성공한 플레이어의 **전체 이동 경로**를 서버에서 그대로 재실행해 유효성·완료 여부·이동 횟수를 검증한다. 타이머도 서버를 기준으로 판정한다. 정답 예시 경로나 시드는 온라인 참가자에게 보내지 않는다.
- **재도전:** 성공 후 2분 안에 다시 풀어 더 낮은 기록을 제출할 수 있다. 동률일 때는 해당 기록을 먼저 제출한 참가자가 앞선다.
- **재접속:** 같은 브라우저 탭에서 잠깐 연결이 끊겨도 임시 참가 토큰을 사용해 복귀한다. 게임 중 새로고침을 하면 **그때까지 서버에 제출한 최고 기록은 유지되지만, 아직 제출하지 않은 로컬 이동 기록은 초기화된다.**

## Windows CMD에서 실행

Node.js **20 이상**을 설치한다. Windows에서는 압축 해제 후 `start-windows.cmd`를 더블클릭해도 된다.

```cmd
cd /d "%USERPROFILE%\Downloads\bullet-man"
npm install
npm run dev
```

터미널에 프론트 주소 `http://localhost:5173`과 게임 서버 `http://localhost:3001`이 표시된다. **브라우저는 반드시 `http://localhost:5173`으로 열어야 한다.** `npm run dev`가 프론트엔드와 서버를 동시에 실행한다. 종료하려면 CMD에서 `Ctrl+C`.

가장 간단한 다중 사용자 테스트: 브라우저 일반창에 `http://localhost:5173`을 열고 방을 만든 다음, 다른 브라우저의 시크릿 창에서 해당 **6자리 코드**로 입장한다. 실제로 다른 기기에서 QR을 스캔하려면 공개 배포하거나 **같은 Wi-Fi**에 있는 PC의 사설 IP를 이용한다.

### 같은 Wi-Fi 스마트폰에서 QR 테스트

1. Windows CMD에서 `ipconfig`로 PC의 `IPv4 주소`를 확인한다. 예: `192.168.0.12`.
2. PC도 `http://192.168.0.12:5173`으로 접속한 뒤 방을 만든다. (브라우저 주소가 `localhost`라면 QR도 localhost로 만들어져 휴대폰에서 작동하지 않는다.)
3. 휴대폰을 **같은 Wi-Fi**에 연결하고 QR을 스캔한다. Windows 방화벽에서 해당 Node.js/Vite 개발 서버의 개인 네트워크 접근을 허용해야 할 수 있다.
4. 참가자 두 명 이상이면 방장이 시작한다.

게임 도중 브라우저의 `시계`가 수초 정도 다르게 보일 수 있지만, **경기 마감/점수 인정은 서버의 시각**으로 결정된다.

## 프로덕션 빌드 및 로컬 점검

```cmd
npm test
npm run build
npm start
```

`npm start`로 실행한 서버는 `http://localhost:3001`에서 **프론트엔드 정적 파일과 Socket.IO를 같은 주소로 제공**한다. `PORT` 환경변수로 포트를 바꿀 수 있다.

## 무료 공개 배포 — Render Web Service 한 개

정적 사이트 호스팅 서비스만으로는 자체 Socket.IO 서버가 실행되지 않는다. **프론트와 Node 서버를 함께 배포**해야 QR 초대·실시간 대전이 실제로 작동한다.

1. 프로젝트를 GitHub 저장소에 올린다. `node_modules`, `dist`, `dist-server`는 올리지 않는다.
2. Render에서 **New → Web Service**를 선택하고 저장소를 연결한다. `render.yaml`로 배포 설정을 가져올 수도 있다.
3. 요금제는 **Free**, 빌드 명령은 `npm install --include=dev --no-audit --no-fund && npm run build`, 실행 명령은 `npm start`, 헬스 체크는 `/api/health`로 설정한다.
4. 받은 `https://....onrender.com` 주소로 들어가 방을 만든다. 해당 주소로 QR이 생성되므로 멀리 있는 친구도 설치 없이 참여할 수 있다.

**무료 배포의 한계:** Render 무료 서버는 일정 시간 유휴 상태이면 잠들며 다음 연결에 콜드 스타트가 발생할 수 있다. 이 프로젝트의 방·점수는 **서버 메모리에만 저장**하므로 서버가 잠들거나 재시작·재배포되면 해당 방과 제출 기록이 사라진다. 실서비스로 확장할 때는 영구 DB·공유 세션 저장소·재접속 정책을 추가해야 한다. 무료 운영 한도 및 요금제 조건은 배포 직전에 Render 공식 문서에서 확인하자.

## 폴더 구조

```text
src/engine.ts             모든 이동·퍼즐 생성 로직
src/GameBoard.tsx          혼자 하기와 대전이 공유하는 게임판/조작
src/SoloGame.tsx           연습 모드
src/OnlineGame.tsx         웹소켓 클라이언트·QR 대기방·대전 UI
src/multiplayer.ts         프론트와 서버 공통 타입
server/rooms.ts            방 상태·초대·타이머·서버측 풀이 검증
server/index.ts            HTTP + Socket.IO 서버, 프로덕션 정적 파일 호스팅
server/rooms.test.ts       방·서버 판정 단위 테스트
render.yaml                Render 무료 Web Service 설정
```

### 베타에서 제공하지 않는 기능

불특정 사용자 랜덤 매칭, 로그인, 전 세계 랭킹, 서버 재시작 후 방 복원, 서버 간 분산 확장은 아직 없다. 이 버전은 **QR 초대로 친구와 하는 2~8인 온라인 대전**에 집중한다.

### 브랜드 안내

다른 퍼즐 게임의 규칙에서 영감을 얻은 독립적인 그래픽/UI 프로토타입이다. 상용 배포 전에 기존 게임의 이름·로고·아트워크 권리 문제를 별도 검토한다.
